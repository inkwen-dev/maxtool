# 环境配置方案

## 一、环境规划

### 1.1 环境类型

**开发环境（dev）：**
- 数据库：本地 PostgreSQL
- 部署：本地开发（localhost:3002）
- 用途：开发、测试

**生产环境（prod）：**
- 数据库：Supabase PostgreSQL（云服务）
- 部署：Vercel
- 用途：正式上线

---

## 二、数据库选择

### 2.1 开发环境：本地 PostgreSQL

**选择原因：**
- ✅ 与生产环境一致，避免兼容性问题
- ✅ 本地开发，访问速度快
- ✅ 免费，无需额外成本

**配置：**
- 数据库类型：PostgreSQL
- 版本：PostgreSQL 13+（推荐）
- 连接：本地连接

---

### 2.2 生产环境：Supabase PostgreSQL

**选择原因：**
- ✅ 免费额度足够（500MB存储）
- ✅ 自动备份
- ✅ 全球CDN
- ✅ 适合国外用户

**配置：**
- 数据库类型：PostgreSQL
- 存储：500MB（免费版）
- 连接：全球CDN

---

## 四、数据库适配层

### 4.1 数据库客户端封装

**文件：`lib/database.ts`**

代码会自动检测连接方式：
- 如果提供了 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY`，使用 Supabase 客户端
- 如果提供了 `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`，使用直接 PostgreSQL 连接
- 如果两者都提供，优先使用 Supabase

**统一接口：**
```typescript
// 插入使用统计
export async function insertUsageStats(toolName: string): Promise<void>

// 查询使用统计
export async function getUsageStats(toolName?: string)
```

**优势：**
- ✅ 应用代码无需关心连接方式
- ✅ 表结构统一，业务逻辑一致
- ✅ 通过环境变量自动切换连接方式

## 六、环境切换

### 6.1 自动检测

代码会自动检测环境变量，选择连接方式：

```typescript
// lib/database.ts
function detectConnectionType(): ConnectionType {
  // 优先使用 Supabase（如果提供了 URL 和 Key）
  if (process.env.SUPABASE_URL && process.env.SUPABASE_ANON_KEY) {
    return 'supabase'
  }
  
  // 使用直接 PostgreSQL 连接（如果提供了连接信息）
  if (process.env.DB_HOST && process.env.DB_USER && process.env.DB_PASSWORD && process.env.DB_NAME) {
    return 'postgresql'
  }
  
  throw new Error('Missing database configuration')
}
```

## 八、开发环境设置

### 8.1 本地 PostgreSQL 设置

**步骤：**
1. 安装 PostgreSQL（如果还没有）
2. 启动 PostgreSQL 服务
3. 创建数据库（如：`max_tool`）
4. 执行 SQL 脚本创建表（见 `docs/上线资源/数据库设计-postgresql.sql`）
5. 配置环境变量（`.env.local`）
6. 测试连接

**连接信息示例：**
- 主机：`localhost`
- 端口：`5432`
- 用户名：`postgres`
- 密码：`your-password`
- 数据库：`max_tool`

---

### 8.2 本地开发配置

**步骤：**
1. 复制 `env.example` 为 `.env.local`
2. 填写本地 PostgreSQL 连接信息
3. 安装依赖：`npm install`（已包含 `pg`）
4. 测试连接：运行 `npm run dev`，查看控制台输出

---

## 九、生产环境设置
