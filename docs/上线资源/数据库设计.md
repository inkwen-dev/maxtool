# 数据库设计

## 一、数据库选择

项目使用 **PostgreSQL** 数据库，支持两种连接方式：

### 本地开发环境
- **数据库**：本地 PostgreSQL
- **用途**：本地开发测试
- **配置**：通过 `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` 连接

### 生产环境（Supabase）
- **数据库**：Supabase PostgreSQL
- **用途**：生产环境部署
- **配置**：通过 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY` 连接

---

## 二、表结构设计

### 使用统计表（usage_stats）

**用途**：记录每个工具的使用次数和时间，用于分析热门工具

**表结构：**

| 字段名 | 类型 | 说明 | 是否必填 |
|--------|------|------|---------|
| `id` | UUID DEFAULT gen_random_uuid() | 主键，唯一标识 | 是 |
| `tool_name` | VARCHAR(100) | 工具名称（如：'draw-lots'） | 是 |
| `created_at` | TIMESTAMP DEFAULT NOW() | 使用时间 | 是 |

**设计说明：**
- ✅ **当前设计**：只记录工具名称和使用时间，满足MVP阶段需求
- ✅ **隐私友好**：不记录IP、浏览器等个人信息，符合隐私法规
- ✅ **存储高效**：每条记录仅约20-30字节，存储成本极低
- ⚠️ **未来扩展**：如需IP、浏览器等信息，参考[数据库设计扩展分析.md](./数据库设计扩展分析.md)

**索引：**
- `idx_tool_name`：按工具名称查询（统计某个工具的使用次数）
- `idx_created_at`：按时间查询（分析使用趋势）

## 四、数据操作示例

### 插入数据

**使用 Supabase 客户端：**
```typescript
await supabaseClient
  .from('usage_stats')
  .insert({ tool_name: 'draw-lots' })
```

**使用直接 PostgreSQL 连接：**
```typescript
await pgPool.query(
  'INSERT INTO usage_stats (tool_name) VALUES ($1)',
  ['draw-lots']
)
```

**统一接口（适配层）：**
```typescript
await insertUsageStats('draw-lots')  // 自动适配 Supabase 或直接 PostgreSQL 连接
```

---

### 查询数据

```sql
SELECT COUNT(*) as count 
FROM usage_stats 
WHERE tool_name = 'draw-lots';
```

## 六、环境配置

### 本地 PostgreSQL 配置

**环境变量：**
```env
NODE_ENV=development
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your-password
DB_NAME=your-database-name
```

**配置步骤：**
1. 确保本地 PostgreSQL 已安装并运行
2. 创建数据库
3. 执行 PostgreSQL SQL 脚本（见 [数据库设计-postgresql.sql](./数据库设计-postgresql.sql)）
4. 配置 `.env.local` 文件
5. 测试连接

---

### Supabase 配置

**环境变量：**
```env
NODE_ENV=production
SUPABASE_URL=https://xxx.supabase.co
SUPABASE_ANON_KEY=xxx
```

**配置步骤：**
1. 创建 Supabase 项目
2. 在 SQL Editor 中执行 PostgreSQL SQL 脚本
3. 获取连接信息（Project URL 和 Anon Key）
4. 配置环境变量（Vercel 或 `.env.local`）
5. 测试连接

## 七、数据库适配层

### 统一接口设计

**文件：`lib/database.ts`**

代码会自动检测连接方式：
- 如果提供了 `SUPABASE_URL` 和 `SUPABASE_ANON_KEY`，使用 Supabase 客户端
- 如果提供了 `DB_HOST`, `DB_USER`, `DB_PASSWORD`, `DB_NAME`，使用直接 PostgreSQL 连接
- 如果两者都提供，优先使用 Supabase

**优势：**
- ✅ 应用代码无需关心连接方式
- ✅ 表结构统一，业务逻辑一致
- ✅ 通过环境变量自动切换连接方式
