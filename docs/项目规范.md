## 二、SEO配置

### 2.1 Metadata配置

**核心文件：** `lib/metadata.ts`

#### 基础Metadata生成

所有页面使用统一的 `generateBaseMetadata()` 函数生成基础metadata：

```typescript
export function generateBaseMetadata(overrides?: Partial<Metadata>): Metadata {
  return {
    metadataBase: new URL(siteConfig.url),
    title: {
      default: siteConfig.name,
      template: `%s | ${siteConfig.name}`,  // 页面标题模板
    },
    description: siteConfig.description,
    keywords: siteConfig.keywords,
    // Open Graph (Facebook分享)
    openGraph: {
      type: 'website',
      locale: siteConfig.locale,
      url: siteConfig.url,
      siteName: siteConfig.name,
      title: siteConfig.name,
      description: siteConfig.description,
    },
    // Twitter Cards
    twitter: {
      card: 'summary_large_image',
      title: siteConfig.name,
      description: siteConfig.description,
    },
    // 搜索引擎爬虫指令
    robots: {
      index: true,
      follow: true,
      googleBot: {
        index: true,
        follow: true,
        'max-video-preview': -1,
        'max-image-preview': 'large',
        'max-snippet': -1,
      },
    },
  }
}
```

#### 工具页面Metadata

使用 `generateToolMetadata()` 为工具页面生成动态metadata：

```typescript
generateToolMetadata(toolName, toolDescription, toolPath)
```

**特性：**
- 自动生成工具名称标题
- 包含工具描述
- 添加工具相关关键词
- 设置Canonical URL

#### 分类页面Metadata

使用 `generateCategoryMetadata()` 为分类页面生成动态metadata：

```typescript
generateCategoryMetadata(categoryName, categoryPath, toolCount)
```

**特性：**
- 动态生成分类标题
- 包含工具数量信息
- 添加分类相关关键词

### 2.2 Robots.txt配置

**文件：** `app/robots.ts`

```typescript
export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      {
        userAgent: '*',
        allow: '/',
        disallow: ['/api/'],  // 禁止爬取API路由
      },
    ],
    sitemap: `${siteConfig.url}/sitemap.xml`,
  }
}
```

**配置说明：**
- 允许所有搜索引擎爬虫访问
- 禁止爬取 `/api/` 路由（API接口）
- 指向sitemap.xml位置

**访问地址：** `https://maxtool.me/robots.txt`

### 2.3 Sitemap.xml配置

**文件：** `app/sitemap.ts`

#### 包含的页面类型

1. **静态页面**
   - 首页：`priority: 1.0`, `changefreq: 'daily'`
   - 所有工具列表：`priority: 0.9`, `changefreq: 'weekly'`
   - 热门工具：`priority: 0.9`, `changefreq: 'weekly'`
   - 关于/联系/隐私/条款：`priority: 0.5`, `changefreq: 'monthly'`

2. **分类页面**
   - 所有分类：`priority: 0.8`, `changefreq: 'weekly'`
   - 自动包含所有分类（Random, Time, Text, Utilities, Other）

3. **工具页面**
   - 所有20个工具：`priority: 1.0`, `changefreq: 'daily'`
   - 自动包含所有工具页面

#### 优先级规则

| 页面类型 | Priority | Change Frequency | 说明 |
|---------|----------|------------------|------|
| 首页、工具页面 | 1.0 | daily | 最重要，更新频繁 |
| 列表页面 | 0.9 | weekly | 次重要 |
| 分类页面 | 0.8 | weekly | 重要 |
| 静态页面 | 0.5 | monthly | 一般重要 |
| 法律页面 | 0.3 | monthly | 低优先级 |

**访问地址：** `https://maxtool.me/sitemap.xml`

**自动更新：** 添加新工具或分类时，sitemap会自动包含新页面

## 三、JSON-LD结构化数据

**核心文件：** `lib/structured-data.ts`  
**组件：** `components/shared/StructuredData.tsx`

### 3.1 结构化数据类型

#### 1. 网站结构化数据（WebSite）

**使用位置：** `app/layout.tsx`（全局）

```typescript
generateWebsiteStructuredData()
```

**包含信息：**
- 网站名称和URL
- 网站描述
- 发布者信息（Organization）
- 搜索功能（SearchAction）

#### 2. 工具页面结构化数据（WebApplication）

**使用位置：** 所有工具页面（20个工具）

```typescript
generateToolStructuredData(tool)
```

**包含信息：**
- 工具名称和描述
- 工具URL
- 应用类别（UtilityApplication）
- 价格信息（免费）
- 功能列表
- 评分信息

#### 3. 分类页面结构化数据（CollectionPage）

**使用位置：** 所有分类页面

```typescript
generateCategoryStructuredData(categoryName, categoryPath, toolCount)
```

**包含信息：**
- 分类名称和URL
- 分类描述
- 工具数量
- 列表项信息

#### 4. 面包屑导航结构化数据（BreadcrumbList）

**使用位置：** 所有有面包屑的页面

```typescript
generateBreadcrumbStructuredData(breadcrumbItems)
```

**包含信息：**
- 导航层级结构
- 每个层级的名称和URL
- 位置信息

### 3.2 使用位置

| 页面类型 | 结构化数据类型 | 文件位置 |
|---------|--------------|---------|
| 全局布局 | WebSite | `app/layout.tsx` |
| 首页 | WebSite | `app/page.tsx` |
| 工具页面 | WebApplication + BreadcrumbList | `app/tools/[tool-id]/page.tsx` |
| 分类页面 | CollectionPage + BreadcrumbList | `app/category/[category]/page.tsx` |

### 3.3 实现方式

使用 `StructuredData` 组件在页面中注入JSON-LD：

```tsx
<StructuredData data={generateToolStructuredData(tool)} />
```

**输出格式：**
```html
<script type="application/ld+json">
{
  "@context": "https://schema.org",
  "@type": "WebApplication",
  ...
}
</script>
```

## 四、URL路径结构

### 4.1 路径规划

#### 核心页面路径

```
/                          → 首页
/all-tools                 → 所有工具列表
/popular                   → 热门工具
/category/[category]       → 分类页面（动态路由）
/tools/[tool-name]         → 工具详情页（20个工具）
/about                     → 关于页面
/contact                   → 联系页面
/privacy                   → 隐私政策
/terms                     → 服务条款
```

#### 动态路由规则

1. **分类页面**：`/category/[category]`
   - 支持的分类：`random`, `time`, `text`, `utilities`, `other`
   - 自动转换为首字母大写：`Random`, `Time`, `Text`, `Utilities`, `Other`

2. **工具页面**：`/tools/[tool-name]`
   - 工具ID使用kebab-case（小写+连字符）
   - 示例：`/tools/draw-lots`, `/tools/random-number`

### 4.2 命名规范

#### URL Slug规范

- ✅ **使用小写字母**：`/tools/draw-lots`（正确）
- ❌ **不使用大写**：`/tools/DrawLots`（错误）
- ✅ **使用连字符分隔**：`/tools/draw-lots`（正确）
- ❌ **不使用下划线**：`/tools/draw_lots`（错误）
- ❌ **不使用空格**：`/tools/draw lots`（错误）

#### 路径层级

- **扁平化设计**：最多2层路径深度
- **语义化命名**：路径名称直观易懂
- **RESTful风格**：符合REST API设计原则

#### 可扩展性

- 动态路由支持新增分类和工具，无需修改路由配置
- 新工具自动包含在sitemap中
- 新分类自动生成分类页面

### 4.3 SEO友好性

- ✅ URL结构简洁，关键词明确
- ✅ 使用连字符分隔（SEO友好）
- ✅ 路径层级浅，易于爬虫索引
- ✅ 所有页面都有Canonical URL
- ✅ 面包屑导航提供层级结构

## 五、主题样式

### 5.1 主题配置

**核心文件：** `components/shared/ThemeProvider.tsx`

#### 支持的主题

- **Light Mode（浅色模式）**：默认主题
- **Dark Mode（深色模式）**：暗色主题

#### 主题切换机制

1. **用户偏好存储**
   - 使用 `localStorage` 存储用户选择的主题
   - Key: `theme`
   - 值: `'light'` 或 `'dark'`

2. **系统偏好检测**
   - 如果用户未选择主题，自动检测系统偏好
   - 使用 `window.matchMedia('(prefers-color-scheme: dark)')`

3. **初始化脚本**
   - 在 `app/layout.tsx` 的 `<head>` 中执行
   - 防止页面闪烁（FOUC - Flash of Unstyled Content）

### 5.2 实现方式

#### ThemeProvider组件

```tsx
<ThemeProvider>
  <Navigation />
  <main>{children}</main>
  <Footer />
</ThemeProvider>
```

#### 主题切换按钮

位置：`components/shared/Footer.tsx`

功能：
- 显示当前主题
- 点击切换主题
- 实时更新UI

#### CSS变量

使用Tailwind CSS的暗色模式支持：

```css
/* 浅色模式 */
.bg-gray-50 { background-color: #f9fafb; }

/* 深色模式 */
.dark .bg-gray-900 { background-color: #111827; }
```

### 5.3 样式规范

#### 颜色系统

- **主色调**：使用 `accent` 颜色（可在 `globals.css` 中配置）
- **背景色**：`bg-gray-50` (light) / `bg-gray-900` (dark)
- **文本色**：`text-gray-900` (light) / `text-gray-100` (dark)
- **卡片背景**：`bg-white` (light) / `bg-gray-800` (dark)

#### 响应式设计

- 移动端优先（Mobile First）
- 断点：`sm: 640px`, `md: 768px`, `lg: 1024px`, `xl: 1280px`
- 所有组件支持响应式布局

## 九、代码语言规范

### 9.1 代码语言要求

**核心原则：** 所有源码文件（除 `docs/` 目录外）必须使用英文。

#### 必须使用英文的内容

1. **代码注释**
   - ✅ 单行注释：`// Comment`
   - ✅ 多行注释：`/* Comment */`
   - ✅ JSDoc注释：`/** Comment */`

2. **变量和函数命名**
   - ✅ 变量名：`const userName = ...`
   - ✅ 函数名：`function getUserData() {...}`
   - ✅ 类型名：`interface UserData {...}`

3. **错误信息**
   - ✅ 错误消息：`throw new Error('Invalid input')`
   - ✅ 控制台输出：`console.log('User logged in')`

4. **字符串字面量**
   - ✅ 用户可见文本：已在UI组件中处理
   - ✅ 内部字符串：`const status = 'active'`

5. **文档字符串**
   - ✅ JSDoc注释：`/** Function description */`
   - ✅ 函数说明：`// This function does...`

#### 允许使用中文的内容

- ✅ `docs/` 目录下的所有文档文件
- ✅ `README.md`（项目说明文档）
- ✅ `env.example`（环境变量示例文件中的注释）

#### 禁止使用中文的内容

- ❌ 所有源码文件（`app/`, `components/`, `lib/`, `types/`）
- ❌ 代码注释
- ❌ 变量和函数命名
- ❌ 错误消息
- ❌ 控制台输出
- ❌ 配置文件中的注释（除 `env.example`）

### 9.2 代码注释规范

#### 注释风格

**单行注释：**
```typescript
// Initialize database connection
export function initDatabase() { ... }
```

**多行注释：**
```typescript
/**
 * Initialize database connection
 * Supports both Supabase and direct PostgreSQL connection
 */
export function initDatabase() { ... }
```

**行内注释：**
```typescript
const maxConnections = 10 // Maximum number of connections
```

#### 注释内容要求

- ✅ 使用英文描述功能
- ✅ 说明复杂逻辑的原因
- ✅ 解释非显而易见的代码
- ✅ 标注TODO和FIXME

### 9.3 命名规范

#### 变量命名

- ✅ 使用英文单词：`userName`, `toolCount`
- ✅ 使用驼峰命名：`camelCase`
- ✅ 布尔值使用 `is/has/should` 前缀：`isActive`, `hasPermission`

#### 函数命名

- ✅ 使用动词开头：`getUserData()`, `validateInput()`
- ✅ 使用描述性名称：`calculateTotalPrice()`
- ✅ 避免缩写：`getUser()` 而不是 `getUsr()`

#### 类型命名

- ✅ 接口使用 PascalCase：`interface UserData {...}`
- ✅ 类型别名使用 PascalCase：`type ToolName = ...`
- ✅ 枚举使用 PascalCase：`enum Status {...}`

### 9.4 错误处理规范

#### 错误消息

- ✅ 使用英文错误消息
- ✅ 提供清晰的错误描述
- ✅ 包含上下文信息

**示例：**

#### 控制台输出

- ✅ 使用英文日志消息

- ✅ 包含必要的上下文信息

**示例：**
