# 环境变量配置详解

## 🎯 三个核心问题解答

### 问题 1：如果不提交到 Git，Vercel 等托管平台怎么启动项目？

**答案：使用平台的环境变量配置功能**

#### Vercel 环境变量配置

**步骤：**

1. **登录 Vercel Dashboard**
   - 访问 [vercel.com](https://vercel.com)
   - 进入你的项目

2. **配置环境变量**
   - 进入项目 Settings → Environment Variables
   - 点击 "Add New"
   - 添加每个环境变量：
     - **Key**: `DB_HOST`
     - **Value**: `localhost` (本地 PostgreSQL) 或 Supabase URL
     - **Environment**: Production（或 Preview、Development）

3. **添加所有需要的变量**
   ```
   NODE_ENV=production
   DB_TYPE=postgresql
   SUPABASE_URL=https://xxx.supabase.co
   SUPABASE_ANON_KEY=xxx
   ```

4. **重新部署**
   - 配置完成后，Vercel 会自动重新部署
   - 或手动触发部署

**优势：**
- ✅ 安全：敏感信息不提交到代码仓库
- ✅ 灵活：不同环境可以配置不同的值
- ✅ 方便：在 Dashboard 中管理，无需修改代码

---

### 问题 2：项目启动时，怎么知道使用哪个配置文件？

**答案：Next.js 有固定的环境变量加载顺序和优先级**

#### Next.js 环境变量加载顺序

Next.js 按以下顺序加载环境变量（后面的会覆盖前面的）：

1. **系统环境变量**（优先级最高）
2. **`.env.local`**（本地开发，不提交到 Git）
3. **`.env.development`**（开发环境）
4. **`.env.production`**（生产环境）
5. **`.env`**（默认，所有环境）

**优先级：系统环境变量 > .env.local > .env.[环境] > .env**

#### 环境判断逻辑

**Next.js 如何判断环境：**

```typescript
// Next.js 自动判断环境
process.env.NODE_ENV
// 'development' - 开发环境（npm run dev）
// 'production' - 生产环境（npm run build / npm start）
// 'test' - 测试环境（npm test）
```

**项目中的环境判断：**

```typescript
// lib/config.ts
export const config = {
  // 环境（从 NODE_ENV 读取）
  env: process.env.NODE_ENV || 'development',
  
  // 环境配置（不再需要 dbType，代码自动检测）
  
  // 是否为开发环境
  isDev: process.env.NODE_ENV === 'development',
  
  // 是否为生产环境
  isProd: process.env.NODE_ENV === 'production',
}
```

#### 实际加载示例

**开发环境（`npm run dev`）：**

```
1. 读取系统环境变量
2. 读取 .env.local（如果存在）
3. 读取 .env.development（如果存在）
4. 读取 .env（如果存在）
```

**生产环境（`npm run build` + `npm start`）：**

```
1. 读取系统环境变量（Vercel 配置的）
2. 读取 .env.local（如果存在，但生产环境通常没有）
3. 读取 .env.production（如果存在）
4. 读取 .env（如果存在）
```

### 问题 3：系统环境变量怎么传给程序？

**答案：不同平台有不同的方式**

#### 方式 1：Vercel 平台（生产环境）

**在 Vercel Dashboard 配置：**

1. 进入项目 Settings → Environment Variables
2. 添加环境变量
3. Vercel 会自动注入到 `process.env`

**示例：**
```
在 Vercel Dashboard 配置：
DB_HOST=localhost
DB_USER=dev_user
DB_PASSWORD=xxx

程序中使用：
process.env.DB_HOST  // 自动获取
```

---

#### 方式 2：本地开发（Windows）

**方法 A：PowerShell 临时设置**

```powershell
# 设置环境变量（当前会话有效）
$env:DB_HOST="localhost"
$env:DB_USER="dev_user"
$env:DB_PASSWORD="xxx"

# 启动项目
npm run dev
```

**方法 B：系统环境变量（永久）**

1. **打开系统属性**
   - 右键 "此电脑" → "属性"
   - 点击 "高级系统设置"
   - 点击 "环境变量"

2. **添加用户变量**
   - 在 "用户变量" 中点击 "新建"
   - 变量名：`DB_HOST`
   - 变量值：`localhost`（本地 PostgreSQL）
   - 重复添加其他变量

3. **重启终端**
   - 关闭所有 PowerShell/CMD 窗口
   - 重新打开终端
   - 运行 `npm run dev`

**方法 C：使用 .env.local（推荐）**

```env
# .env.local（推荐方式）
DB_HOST=localhost
DB_USER=dev_user
DB_PASSWORD=xxx
```

---

#### 方式 3：Linux/Mac

**临时设置：**
```bash
export DB_HOST="localhost"
export DB_USER="dev_user"
export DB_PASSWORD="xxx"
npm run dev
```

**永久设置：**
```bash
# 编辑 ~/.bashrc 或 ~/.zshrc
export DB_HOST="localhost"
export DB_USER="dev_user"
export DB_PASSWORD="xxx"

# 重新加载
source ~/.bashrc
```

## 📊 环境变量加载优先级（详细）

### Next.js 加载顺序

```
优先级从高到低：

1. 系统环境变量（process.env）
   ↓
2. .env.local（所有环境，不提交到 Git）
   ↓
3. .env.development（仅开发环境）
   ↓
4. .env.production（仅生产环境）
   ↓
5. .env（所有环境，默认值）
```

**重要规则：**
- 后面的会覆盖前面的
- `.env.local` 优先级最高（除了系统环境变量）
- `.env.local` 不会被提交到 Git

## 🔍 实际使用场景

### 场景 1：本地开发

**使用 `.env.local`（推荐）：**

```env
# freetool/.env.local
NODE_ENV=development
# 不再需要 DB_TYPE，代码会自动检测连接方式
DB_HOST=localhost
DB_PORT=3306
DB_USER=dev_user
DB_PASSWORD=xxx
DB_NAME=freetool_dev
```

**程序读取：**
```typescript
// lib/database.ts
const host = process.env.DB_HOST  // 从 .env.local 读取
```

---

### 场景 2：Vercel 生产环境

**在 Vercel Dashboard 配置：**

```
Environment Variables:
- NODE_ENV = production
- DB_TYPE = postgresql
- SUPABASE_URL = https://xxx.supabase.co
- SUPABASE_ANON_KEY = xxx
```

**程序读取：**
```typescript
// lib/database.ts
const supabaseUrl = process.env.SUPABASE_URL  // 从 Vercel 环境变量读取
```

---

### 场景 3：CI/CD 环境

**在 CI/CD 平台配置（如 GitHub Actions）：**

```yaml
# .github/workflows/deploy.yml
env:
  DB_HOST: ${{ secrets.DB_HOST }}
  DB_USER: ${{ secrets.DB_USER }}
  DB_PASSWORD: ${{ secrets.DB_PASSWORD }}
```

**程序读取：**
```typescript
// 自动从 CI/CD 环境变量读取
const host = process.env.DB_HOST
```

## 🎯 最佳实践

### 1. 本地开发

**推荐：使用 `.env.local`**

```env
# .env.local（不提交到 Git）
NODE_ENV=development
# 不再需要 DB_TYPE，代码会自动检测连接方式
DB_HOST=xxx
DB_USER=xxx
DB_PASSWORD=xxx
DB_NAME=freetool_dev
```

**原因：**
- ✅ 简单方便
- ✅ 不提交到 Git，安全
- ✅ 优先级高，不会被覆盖

---

### 2. 生产环境（Vercel）

**推荐：使用 Vercel Dashboard 配置**

```
在 Vercel Dashboard → Settings → Environment Variables 中配置
```

**原因：**
- ✅ 安全：敏感信息不提交到代码
- ✅ 灵活：可以配置不同环境的值
- ✅ 方便：在 Dashboard 中管理

---

### 3. 团队协作

**推荐：使用 `.env.example` + `.env.local`**

```
.env.example（提交到 Git，作为模板）
.env.local（不提交，每个人填写自己的配置）
```

**原因：**
- ✅ `.env.example` 提供配置模板
- ✅ `.env.local` 存储个人配置
- ✅ 团队成员可以快速配置

## 📝 环境变量命名规则

### Next.js 特殊规则

**`NEXT_PUBLIC_` 前缀：**
- 以 `NEXT_PUBLIC_` 开头的变量会暴露到浏览器
- 其他变量只在服务端可用

**示例：**
```env
# 服务端使用（当前项目只在服务端使用 Supabase）
SUPABASE_URL=https://xxx.supabase.co

# 只在服务端可用（安全）
DB_PASSWORD=xxx
```

**使用场景：**
```typescript
// 客户端组件（无法访问服务端变量）
'use client'
const url = process.env.SUPABASE_URL  // ❌ undefined（无法访问）

// 服务端组件（可以访问所有变量）
const password = process.env.DB_PASSWORD  // ✅ 可以访问
const url = process.env.SUPABASE_URL  // ✅ 可以访问
```

## 💡 常见问题

### Q1: 为什么修改 .env.local 后不生效？

**原因：** Next.js 需要重启才能读取新的环境变量

**解决：**
1. 停止开发服务器（Ctrl+C）
2. 重新启动：`npm run dev`

---

### Q2: Vercel 部署后环境变量不生效？

**原因：** 需要重新部署

**解决：**
1. 在 Vercel Dashboard 配置环境变量
2. 点击 "Redeploy" 重新部署
3. 或推送代码触发自动部署

---

### Q3: 如何在不同环境使用不同的配置？

**方法 1：使用不同的 .env 文件**

```
.env.development  # 开发环境
.env.production   # 生产环境
.env.local        # 本地覆盖（优先级最高）
```

**方法 2：使用 Vercel 环境变量**

在 Vercel Dashboard 中为不同环境配置不同的值：
- Production
- Preview
- Development

---

### Q4: 系统环境变量和 .env.local 哪个优先级高？

**答案：系统环境变量优先级更高**

```
系统环境变量 > .env.local > .env.[环境] > .env
```
